# Firebase Auth Email Verification Template

Firebase Auth verification emails are generated by Firebase's backend. Flutter
code cannot change the email HTML, sender domain reputation, or whether Gmail
places the message in Spam. Apply these settings in Firebase Console.

## Firebase Console

Open:

`Firebase Console > Authentication > Templates > Email address verification`

Recommended values:

- Sender name: `InnerU`
- From/reply-to email: use a verified domain mailbox when available, for example
  `no-reply@inneru.valenin.com` or `support@inneru.valenin.com`
- Subject: `Verify your InnerU account`

Message:

```text
Hi,

Welcome to InnerU. Please verify your email address so we can finish setting up
your account and keep your wellness data protected.

Verify your email:
%LINK%

If you did not create an InnerU account, you can safely ignore this email.

Thanks,
The InnerU team
```

## Deliverability Checklist

- Use a real custom sending domain instead of the default
  `selfcare-1476e.firebaseapp.com` sender when Firebase/Identity Platform allows
  it for the project.
- Configure SPF, DKIM, and DMARC for the sending domain.
- Use a consistent sender name: `InnerU`.
- Keep the subject short and non-promotional.
- During testing, open the Gmail spam message and click `Report not spam`; Gmail
  said previous messages from the Firebase sender were marked as spam.

## If HTML Branding Is Required

Firebase's default verification email is limited. For a fully designed HTML
email, build a backend endpoint that:

1. Uses Firebase Admin SDK to generate an email verification link.
2. Sends the email through a transactional provider with domain authentication
   such as SendGrid, Mailgun, Postmark, Amazon SES, or SMTP.
3. Uses a branded HTML template and plain-text fallback.
4. Keeps the app login flow checking `user.emailVerified` as it does now.
